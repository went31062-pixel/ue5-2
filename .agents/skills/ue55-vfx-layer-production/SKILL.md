# 从参考到一层可运行特效

用户要实际资产时，交付文件与 UE 运行结果。先确定这一轮的视觉层和版本；沿用已确认的范围。分析结果可来自 [单层分析流程](../ue5-vfx-step-by-step/SKILL.md)，不重新要求用户提供已存在的参考。

## 每轮完成一小层

1. **观察。** 从指定时间内取帧，写本层轮廓、颜色、位置和变化；将观察、实现推测、试做数值分开。没有看到消失过程，不编造原作者寿命。
2. **原理。** 用短表格讲形状由什么承担、材质怎样上色显现、粒子如何出生和结束。视觉层与发射器数量没有固定对应关系。
3. **制作。** 创建真实源文件与 UE 资产。简单几何保留可编辑形状源；软光和噪声按需要使用可用图像工具。模型只在轮廓、曲面或空间结构需要时制作；平面图案可由 Sprite 承载。
4. **验证。** 在目标 UE 版本编译、保存、重新加载，在关卡中看出生、运动、淡出与最终结束。画面不对就修本层，直到这一轮的交付范围得到验证。
5. **交付。** 给本层文件、实际 UE 截图／短视频、四到六行参数表。用户要求逐层确认时，在这里停下，等待明确反馈后再做下一层。反馈是修改本层时，不扩展其他层。

## 资产对应关系

| 内容 | 制作时记录什么 | 必须核对什么 |
| --- | --- | --- |
| 贴图／图案 | 源文件、尺寸、使用 R/RGB/Alpha 哪个通道、线宽与留白 | 黑白预览不等于透明通道；导入设置和实际采样一致 |
| 材质／颜色 | 实际节点、混合模式、颜色、发光和显现控制来源 | 编译成功；空白处是否透出背景；参数能否单独修改 |
| 模型／平面 | 形状、尺寸、UV、朝向、枢轴；没有独立模型时说明承载方式 | 尺度正确，视角变化时能看到，材质引用完整 |
| 粒子／运动 | 每次数量、出生时间、速度／路径、寿命、淡入淡出、循环 | 停止发射与已有粒子消失分开核对；一次性效果能结束 |

只使用这一层需要的功能。静止符号先验证一个粒子，不自动附加烟雾、火花和其他装饰。材质控制显现和粒子生命周期分别记录，避免用降低亮度掩盖粒子仍然活着的问题。

## UE5.5 实际制作路径

读取 [UE5.5 原生制作参考](references/ue55-authoring.md)。优先使用本机版本的真实接口；接口返回成功后仍需要保存和运行验证。已连接编辑器工具时先发现工具与 schema，再执行。

没有实时连接时，贴图导入和材质可用 UE Python。UE5.5 自带 `CascadeToNiagaraConverter` 的转换上下文可用于创建标准 Niagara 发射器、添加模块和 Renderer；必须在完整编辑器初始化后验证，不能假定纯 Python commandlet 可创建 Niagara 图。

依赖插件只启用在本轮独立工程中。不要把第三方 `NiagaraService` 或 UE5.8 `NiagaraToolsets` 写成 UE5.5 内置接口。不要通过改引擎源码弥补任务缺口。

## 验证与反馈

完成标准见 [运行验证与交付](references/verification.md)。创建失败时保留已完成源文件，报告未完成的具体资产和错误；网页动画、结构图和 AI 重画都不能代替 UE 实测。

颜色和发光数值是当前工程里的试做值，不能宣称从成片准确恢复。看不到的原始贴图和节点保持“推测”；自己做出的资产参数可标“已核对”。

每次只解释三件事：做了什么、效果如何、用户可以改哪一项。需要表达帮助时使用 [简单中文](../plain-chinese-explanations/SKILL.md)。示例工程与脚本见 [金色细三角](../../../examples/triangle-line-ue55/README.md)。
